## 1. Project Overview

### What the project does

The SQL AI Agent converts plain English questions (typed or spoken) into validated Oracle SQL queries, executes them against the CIMS RAQ database, and returns results — no SQL knowledge required.

### Business Purpose

CIMS RAQ contains dozens of Oracle tables for RBI regulatory reports (SEC1–SEC9). Extracting ad-hoc data normally requires deep SQL expertise. This agent removes that barrier for compliance officers and analysts at South Indian Bank.

### Main Features

- **Text queries** — type a question, get live Oracle data
- **Voice queries** — speak in any Indian language, Sarvam AI transcribes to English
- **Semantic search** — FAISS + BGE embeddings find the right tables and columns automatically
- **SQL safety** — SELECT-only enforcement; DELETE/UPDATE/DROP are always blocked
- **Web UI** — React frontend with text and voice tabs, dark mode support

### Technologies Used

| Layer | Technology |
|---|---|
| Backend API | Python, FastAPI, Uvicorn |
| LLM | Ollama (`gpt-oss:120b-cloud` / `mistral`) |
| Embeddings | `BAAI/bge-large-en` via sentence-transformers |
| Vector Search | FAISS (IndexFlatIP) |
| Database | Oracle DB (oracledb thin mode) |
| Speech-to-Text | Sarvam AI `saaras:v2.5` |
| Frontend | React 18, Vite, Tailwind CSS |

## 4. Setup & Installation

### Prerequisites

- Python 3.11+
- Node.js 18+
- [Ollama](https://ollama.com/download) installed
- Oracle DB accessible (host, port, service name, credentials)
- Sarvam AI API key (for voice) — [dashboard.sarvam.ai](https://dashboard.sarvam.ai)

### Python Setup

```bash
# Create and activate virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1          # Windows
# source .venv/bin/activate         # Linux / macOS

# Install dependencies
pip install -r requirements.txt
```

### Node Setup (Frontend)

```bash
cd frontend
npm install
```

### Environment / Database Setup

Edit `src/config.py` with your actual values:

```python
DB_HOST     = "your.oracle.host"
DB_PORT     = 1521
DB_SERVICE  = "XE"
DB_USER     = "your_user"
DB_PASSWORD = "your_password"

OLLAMA_MODEL   = "mistral"          # or gpt-oss:120b-cloud
SARVAM_API_KEY = "sk_your_key"
```

### Build FAISS Indexes (run once — needs Oracle DB)

```bash
python main.py
```

This creates everything inside `output/`. Re-run whenever `data/schema.sql` changes.

### Run Commands

```bash
# Terminal 1 — Ollama LLM server
ollama serve
ollama pull mistral            # pull model if not already downloaded

# Terminal 2 — Python API
uvicorn api.main:app --reload --port 8000

# Terminal 3 — React frontend
cd frontend
npm run dev                    # → http://localhost:5173
```

> API interactive docs: **http://localhost:8000/docs**

## 6. Application Workflow

### Step-by-Step Request Flow (Text Query)

```
Step 1 — User sends POST /api/query
         { "query": "Show NPA for latest quarter", "dialect": "Oracle" }

Step 2 — Schema Retrieval  (src/retriever.py)
         embed_query(query) → 1024-dim vector
         FAISS search:
           table_index.faiss   → Top 3 tables
           column_index.faiss  → Top 5 columns
           row_label_index.faiss → Top 10 label values
                                   e.g. PERIOD_DELINQUENCY = 'C. Total ( A + B)'

Step 3 — Prompt Building  (src/sql_generator.py → build_prompt())
         Combines: schema context + row labels + query rules + user question

Step 4 — SQL Generation  (Ollama LLM — streaming)
         Raw output → strip markdown fences → strip trailing semicolon

Step 5 — SQL Validation
         ✓ Must start with SELECT
         ✗ Block: delete / update / drop / insert / truncate / alter / create / exec

Step 6 — Oracle Execution  (src/executor.py)
         oracledb.connect() → cursor.execute(sql) → fetchmany(100)

Step 7 — JSON Response returned to frontend
```

### Voice Query — Extra First Step

```
Audio file uploaded → POST /api/voice
  └── Sarvam AI saaras:v2.5 (cloud STT)
        └── Returns English transcript
              └── → same Steps 2–7 above
```

## 8. Core Modules Explanation

---

### `src/config.py`

**Purpose**: Central settings file — single place for all DB credentials, model names, top-K values, and API keys.

**Core logic**: Plain Python constants. Every other `src/` module imports from here.

```python
EMBED_MODEL  = "BAAI/bge-large-en"               # embedding model
QUERY_PREFIX = "Represent this sentence for searching relevant passages: "

TOP_K_TABLES  = 3   # how many tables FAISS returns per query
TOP_K_COLUMNS = 5   # how many columns FAISS returns per query

OLLAMA_URL   = "http://localhost:11434/api/generate"
OLLAMA_MODEL = "gpt-oss:120b-cloud"

DB_HOST, DB_PORT, DB_SERVICE = "...", 1521, "XE"
DB_USER, DB_PASSWORD = "...", "..."
DB_MAX_ROWS  = 100                                # Oracle row fetch cap

SARVAM_API_KEY = "sk_..."                         # voice transcription
```

**Used by**: every `src/` module and `api/routes/`.

---

### `src/parser.py`

**Purpose**: Parses raw Oracle DDL (`data/schema.sql`) into a Python dict of tables and columns.

**Core logic**: Uses two compiled regex patterns:
- `TABLE_PATTERN` — matches `CREATE TABLE "name" ( ... );` blocks
- `COLUMN_PATTERN` — matches each column definition line (`name TYPE`)
- Skips constraint lines (`PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, etc.)

```python
# Input:  CREATE TABLE "CIMS_RAQ_Q_SEC1_PART_A_DOM" ( "PERIOD_DELINQUENCY" VARCHAR2(200), ... );
# Output: { "cims_raq_q_sec1_part_a_dom": [{"name": "period_delinquency", "type": "varchar2"}, ...] }

tables = parse_sql_schema(open("data/schema.sql").read())
```

**Used by**: `main.py` → feeds into `formatter.py`

---

### `src/formatter.py`

**Purpose**: Converts the parsed schema dict into two things:
1. `output/schema.json` — human-readable schema used by `sql_generator.py`
2. Vector records — plain-text sentences used as input for embedding

**Core logic**:

```python
# build_schema_json() — adds auto-generated descriptions to each table/column
{
  "table": "cims_raq_q_sec1_part_a_dom",
  "description": "stores loan and repayment data",
  "columns": [{"name": "gross_npa_end", "description": "value of gross npa end"}],
  "text": "cims_raq_q_sec1_part_a_dom table stores data including period_delinquency, gross_npa_end ..."
}

# build_vector_records() — creates embeddable sentences
table_records  → [{"text": "cims_raq_q_sec1... stores loan...", "table": "..."}]
column_records → [{"text": "table.column represents description", "table": "...", "column": "..."}]
```

**Used by**: `main.py` → outputs feed into `vectorizer.py`

---

### `src/vectorizer.py`

**Purpose**: Converts text into 1024-dim vectors using `BAAI/bge-large-en` and builds/saves FAISS indexes.

**Core logic**:

```python
model = SentenceTransformer("BAAI/bge-large-en")

# Documents embedded without prefix (symmetric)
embed_documents(texts)  →  model.encode(texts, normalize_embeddings=True)

# Queries embedded WITH prefix (asymmetric retrieval — required by BGE)
embed_query(query)  →  model.encode([QUERY_PREFIX + query], normalize_embeddings=True)[0]

# IndexFlatIP = exact cosine similarity (vectors are L2-normalized, so IP = cosine)
build_faiss_index(vectors)  →  faiss.IndexFlatIP(dim); index.add(vectors)

# Saves two files per index: .faiss (vectors) + .pkl (metadata list)
save_index(index, meta, "output/table_index.faiss", "output/table_meta.pkl")
```

**Used by**: `main.py`, `description_fetcher.py`

---

### `src/retriever.py`

**Purpose**: Searches all three FAISS indexes to find the tables, columns, and row-label values most relevant to the user's query.

**Core logic**:

```python
def get_relevant_schema(query):
    # Load index from disk, embed query, run similarity search
    tables  = search("output/table_index.faiss",  "output/table_meta.pkl",  query, k=3)
    columns = search("output/column_index.faiss", "output/column_meta.pkl", query, k=5)

    # Filter columns to only those belonging to matched tables
    table_names = {t["table"] for t in tables}
    columns = [c for c in columns if c["table"] in table_names]

    # L2 index: find exact Oracle label strings closest to query
    labels = search_labels(query, table_names, top_k=10)

    return tables, columns, labels
```

The returned `labels` (e.g. `PERIOD_DELINQUENCY = 'C. Total ( A + B)'`) are injected directly into the LLM prompt so WHERE clauses are exact.

**Used by**: `api/routes/query.py`, `api/routes/voice.py`

---

### `src/sql_generator.py`

**Purpose**: Builds a structured LLM prompt, calls Ollama to generate SQL, post-processes the output, and validates it for safety.

**Core logic — three parts:**

**1. Prompt builder** (`build_prompt`): Assembles a detailed prompt containing:
- Schema context (table names, allowed columns, row labels)
- Hard rules for the LLM: vertical table rules, DOM/OVE column rules, date rules, JOIN rules, TOP-N rules

**2. SQL generator** (`generate_sql`): Streams Ollama API response token-by-token, then cleans the output:
```python
response = requests.post(OLLAMA_URL, json={..., "stream": True}, timeout=300, stream=True)
raw = "".join(json.loads(line)["response"] for line in response.iter_lines() if line)
raw = re.sub(r'^```(?:sql)?\s*', '', raw.strip())   # strip markdown fences
raw = raw.rstrip(";")                                # Oracle rejects trailing semicolons
```

**3. Validator** (`validate_sql`): Security gate — runs before any DB execution:
```python
BANNED_KEYWORDS = ["delete", "update", "drop", "insert", "truncate", "alter", "create", "exec"]

if not sql.lower().startswith("select"):
    return False, "Only SELECT queries are allowed"
for word in BANNED_KEYWORDS:
    if re.search(rf'\b{word}\b', sql.lower()):
        return False, f"Dangerous keyword detected: '{word}'"
```

**Used by**: `api/routes/query.py`, `api/routes/voice.py`

---

### `src/executor.py`

**Purpose**: Connects to Oracle DB using `oracledb` and runs the validated SQL query.

**Core logic**:

```python
def execute_query(sql):
    dsn    = oracledb.makedsn(DB_HOST, DB_PORT, service_name=DB_SERVICE)
    conn   = oracledb.connect(user=DB_USER, password=DB_PASSWORD, dsn=dsn)
    cursor = conn.cursor()
    cursor.execute(sql.rstrip(";"))                   # Oracle rejects trailing semicolons
    columns = [col[0] for col in cursor.description]  # column names from cursor
    rows    = cursor.fetchmany(DB_MAX_ROWS)            # cap at 100 rows
    return columns, rows, None                        # None = no error
```

- Uses **oracledb thin mode** — no Oracle Instant Client installation required
- Returns `(columns, rows, error)` — if an exception occurs, `error` is a string message

**Used by**: `api/routes/query.py`, `api/routes/voice.py`

---

### `src/description_fetcher.py`

**Purpose**: Queries Oracle DB for distinct row-label values (e.g. all unique values in `PERIOD_DELINQUENCY`, `INDUSTRY_NAME`, `DESCRIPTION`) and builds the L2 FAISS index over them.

**Core logic**:x

```python
# Label columns recognized across all CIMS tables
LABEL_COLUMNS = {"description", "item", "category", "industry_name",
                 "period_delinquency", "risk_category", "country_brw_cuntr_party", ...}

# fetch_and_save(): queries Oracle for DISTINCT values
SELECT DISTINCT {col} FROM {table} WHERE {col} IS NOT NULL AND ROWNUM <= 50
# → saves output/description_samples.json: { table: { col: [val1, val2, ...] } }

# build_and_save_label_index(): embeds each value as:
# "cims_raq_q_sec1_part_a_dom period_delinquency label: C. Total ( A + B)"
# → saves output/row_label_index.faiss + row_label_meta.pkl

# search_labels(): finds closest stored labels for a query at runtime
```

**Why this matters**: CIMS tables store data in vertical (pivoted) format — rows are named metrics. Without exact label strings, the LLM generates wrong WHERE clauses.

**Used by**: `main.py` (index build), `retriever.py` (runtime search)

---

### `src/speech.py`

**Purpose**: CLI-only microphone recorder that captures audio and sends it to Sarvam AI for speech-to-text transcription. Used when running the agent from the terminal (not the web UI).

**Core logic**:

```python
# Captures mic audio using sounddevice at 16kHz mono (required by Sarvam AI)
# Auto-stops on:
#   - 2.5 seconds of continuous silence  (RMS < 0.010 threshold)
#   - User presses Enter  (runs in a background thread)
#   - 20-minute hard cap

# Saves audio to a temp WAV file via soundfile, then POSTs to Sarvam AI:
requests.post(
    "https://api.sarvam.ai/speech-to-text-translate",
    headers={"api-subscription-key": SARVAM_API_KEY},
    files={"file": ("audio.wav", audio_file, "audio/wav")},
    data={"model": "saaras:v2.5"},   # multilingual → English
)
# Returns: (english_text, error)
```

> The web UI does **not** use this file — it uses the browser's MediaRecorder API instead (`frontend/src/hooks/useVoiceRecorder.js`) and uploads directly to `/api/voice`.

**Used by**: CLI / `test.py` only
